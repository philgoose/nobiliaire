## 제안서를 읽기 전에, 화면부터 보십시오

제안서 B블록에 글로 적은 "임원이 직접 업무 도구를 만든다"는 문장을 **먼저 만들어 봤습니다.** 제작에 2시간 걸렸습니다.
설명이 아니라 실제로 작동하는 화면입니다 — 그래프에 마우스를 올려 보시고, 요약 버튼을 직접 눌러 보십시오.

| | 내용 |
|---|---|
| **임원 주간 대시보드** | 핵심 지표 4종 · 월별 추이 · 부서별 달성률. 휴대폰에서도 열립니다. |
| **주간 경영 브리핑** | 5개 부서 보고서 1,420자 → 버튼 한 번에 임원 브리핑. 인쇄하면 결재가 도는 A4 한 장. |

요약만 해 주는 도구는 많습니다. 이 화면이 다른 지점은 마지막 항목입니다 —
**"상품기획 지연과 디자인 지연은 같은 외주 업체 한 곳에서 비롯됨."**
다섯 부서가 따로 올린 보고서를 가로질러 **사람이 놓치는 연결을 집어내는 장면**입니다.

> 화면의 모든 수치는 가상 데이터입니다. NOBILIAIRE의 실제 경영 정보는 일절 사용하지 않았습니다.

## 결정에 필요한 세 줄

| | |
|---|---|
| **무엇을** | 임원 6인이 각자 반복 업무 1건을 워크숍 안에서 직접 도구로 제작 |
| **어떻게** | 3일 집합 · 강의 30%, 임원이 직접 손을 움직이는 시간 70% · 코딩 경험 불필요 |
| **남는 것** | 작동하는 도구 6개와 소스 전부. 권리는 전부 귀사 소유 |

## 검토가 길어지는 이유 세 가지를 먼저 없앴습니다

1. **사전 지식** — 코딩하지 않습니다. 말로 지시해서 만듭니다. 위 화면도 코드를 한 줄도 직접 치지 않고 제작했습니다.
2. **보안** — 사내 데이터 외부 반출 없음. 실습은 가상·샘플 데이터, 실데이터는 귀사 PC 안에서만 다룹니다.
3. **잔존물** — 일차별로 산출물을 끊고, 3일차에 유지·수정 방법까지 인수합니다. 외부 의존을 남기지 않습니다.

## 3일 설계

| | | 산출물 |
|---|---|---|
| **DAY 1** | 업무 1건 선정 → 환경 세팅 → 첫 화면 작동 | 임원별 작동 프로토타입 6개 |
| **DAY 2** | 데이터 연결 · 자동 요약 · 보고서 출력. 귀사 보고 양식에 맞춤 | 실무 투입 가능한 도구 6개 |
| **DAY 3** | 공유 · 배포, 임원이 직접 수정하는 법 | 배포 완료 + 유지 방법 인수 |
